## 2. 本地 API 最小规格

首阶段只规划 OpenAI Chat Completions 兼容的最小子集：

- GET /v1/models
- POST /v1/chat/completions
- stream=true 时使用标准 SSE。
- 支持明确声明的 role/content、temperature、max_tokens 等字段；不支持字段必须返回明确错误或记录为忽略，不可静默误导。
- 每个请求生成独立 requestId，客户端断开后取消上游收集。
- 本地 API 只监听 127.0.0.1 / ::1，不得默认监听 0.0.0.0。
- 使用模块自有 API Key；不得将 DeepSeek 宿主 Token 暴露给调用方。
- 默认关闭跨设备访问；如未来允许，必须单独设计认证、TLS、网络 ACL 和风险确认。

## 3. 数据功能验收

- 数据库版本、表名、主键、外键、索引、WAL 行为必须从实际目标 APK/设备样本确认。
- 读取功能先只读；写入功能必须有事务和备份。
- 恢复前检查版本、完整性和来源，失败时原子回滚。
- 自动备份限制最大数量、总容量和保留天数。
- 不把用户数据库、消息正文、图片或附件提交到 GitHub。

## 4. 网络诊断验收

默认允许采集字段：
- 传输层类型（OkHttp/Cronet/URLConnection/Ktor 等）
- 方法类别（GET/POST 等）
- URL 主机和经过路径脱敏的路由模板
- 状态码、耗时、请求/响应字节数
- 安装状态、异常类型和计数

默认禁止采集：
- Authorization、Cookie、Set-Cookie、API Key
- 查询参数中可能含身份信息的字段
- 请求/响应正文、提示词、模型输出
- 设备 ID、账号 ID、会话 ID
- PoW challenge、solution 或认证材料

## 5. 多账号边界

多账号功能仅管理用户明确输入并愿意保存在模块内的配置档案或 API 配置；不读取 DeepSeek 私有凭据、不自动导出会话 Token、不模拟登录、不提供账号池或账号共享功能。
